## Executive Summary

Studio Moderna processes invoices from suppliers across 12 markets in Central and Eastern Europe. Their finance team manually enters data from approximately 2,800 invoices per month — a mix of structured PDFs, scanned images, and emailed attachments in varying formats and languages. Manual entry takes an estimated 4.5 minutes per invoice; errors require additional reconciliation time.

Kvant proposes an LLM-assisted extraction pipeline that automates initial data capture, reducing manual entry to a review-and-correct workflow. Target: reduce average handling time per invoice from 4.5 minutes to under 90 seconds.

**Proposed budget: €31,000**
**Timeline: 10 weeks**

---

## Problem Statement

The invoice processing problem at Studio Moderna has three distinct layers of complexity:

**Format diversity:** Invoices arrive as machine-readable PDFs, scanned images (varying quality), Excel files, and as text embedded in email bodies. No single extraction approach handles all of these.

**Language diversity:** Supplier invoices arrive in 8 languages: Slovenian, Croatian, Serbian, Czech, Slovak, Polish, Romanian, and German. Field labels vary; "Datum izdaje" and "Datum fakture" and "Rechnungsdatum" all mean invoice date.

**Structure diversity:** No two major suppliers use the same invoice layout. Line item tables vary in column order, labeling, and whether subtotals are included. Some invoices have 2 line items; some have 200.

## Proposed Solution

A three-stage extraction pipeline:

### Stage 1: Ingestion and Preprocessing
- Unified intake: email attachment monitoring (IMAP), S3-compatible drop bucket, manual upload fallback
- Format detection and routing: PDF (text-layer vs. scanned), Excel, plain text
- OCR for scanned PDFs: AWS Textract (recommended) or Azure Document Intelligence — to be evaluated on Studio Moderna sample set
- Table extraction for structured PDFs: pdfplumber with fallback to LLM-based extraction for complex layouts

### Stage 2: LLM Extraction
- GPT-4o processes preprocessed document text/tables
- Extraction target: invoice number, date, supplier name, supplier VAT number, line items (description, quantity, unit price, total), subtotal, VAT amount, total amount, currency, payment terms
- Multilingual: GPT-4o handles all 8 languages natively; field normalization to English in output
- Structured JSON output with per-field confidence scores
- Low-confidence fields flagged for human review

### Stage 3: Validation and Review
- Rule-based validation: totals arithmetic check, date plausibility, VAT number format by country
- Human review UI: invoice image alongside extracted JSON, editable fields, approve/reject/escalate
- Correction logging: all manual corrections stored for future fine-tuning consideration

**Output:** Structured data export in Studio Moderna's required format (CSV, or direct push to their accounting system via API — to be confirmed).

## Scope

**In scope:**
- Ingestion from email (IMAP) and S3 bucket
- OCR preprocessing for scanned documents
- GPT-4o extraction with multilingual support
- Validation layer
- Human review UI (Streamlit)
- CSV export
- Deployment on Studio Moderna's preferred cloud (preference: AWS, EU region)

**Out of scope:**
- Direct integration with accounting/ERP system (Phase 2 — requires API access and scoping with Studio Moderna IT)
- Invoice approval workflows
- Supplier portal or supplier-facing functionality
- Training Studio Moderna staff on the underlying LLM technology (operations training only)

## Assumptions and Risks

The accuracy target (under 90 seconds handling time) is achievable if the extraction accuracy rate is above 85% on required fields — meaning fewer than 15% of invoices require significant manual correction. Based on the 40-document sample, we expect 88–92% accuracy on well-structured PDFs and 78–84% on scanned documents. This will be validated in the discovery phase.

If Studio Moderna's accounting system cannot accept CSV import (some older systems require proprietary formats), the output integration will need to be renegotiated.
