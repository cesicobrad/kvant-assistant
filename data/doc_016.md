# Post-Mortem: Qdrant Migration Breaks Retrieval Quality — Mercator Polica
**Incident date:** October 28–31, 2024
**Type:** Retrieval quality degradation (not outage)
**Author:** Žiga Potočnik
**Date written:** November 5, 2024
**Status:** Final

---

## Summary

Following the NLB outage in September, Matic upgraded the Mercator Polica deployment from Qdrant 1.6.1 to 1.10.0 as part of a general security and dependency update sweep. The upgrade introduced a silent change in default HNSW indexing parameters that degraded retrieval quality on the Mercator corpus from a mean RAGAS context precision of 0.69 to 0.54. The degradation was not detected for four days because we had no automated eval running in production.

This is the second incident in two months where we discovered a problem because user behavior changed, not because our monitoring caught it.

## Root Cause

Qdrant 1.10.0 changed the default HNSW `m` parameter from 16 to 8 for newly created collections. `m` controls the number of connections per node in the HNSW graph — lower values mean faster indexing and less memory but worse recall on approximate nearest-neighbor search. Our collection was recreated during the same maintenance window as the upgrade (we had rebuilt it for an unrelated reason), so it was created with the new defaults. This was not documented in the upgrade notice we read; it was in the migration guide which we did not read.

The practical effect: for Mercator's ~1,100-document corpus, the lower `m` value caused meaningful recall degradation on queries requiring multi-hop or semantically distant retrieval. Simple factual lookups were largely unaffected, which is why casual spot-checking missed it initially.

---

## What Should Have Prevented This

1. **Automated eval in production.** A nightly RAGAS eval run on a fixed 45-question set would have caught this on October 29. We have talked about this since the Mercator post-launch report in August. It is still not implemented. This needs to be on the sprint board, not the backlog.

2. **Read the migration guide, not just the changelog.** Parameter defaults are migration-guide territory. Matic now reads both before any vector DB upgrade.

3. **Do not recreate production collections during the same window as a dependency upgrade.** One change at a time. This is basic and we violated it.

---

## Broader Concern

This is the third quality issue on Mercator Polica. The GPT-4o → GPT-4o-mini downgrade, the date handling problem from the August eval report, and now this. The system is functional but fragile. The follow-up improvements Kvant recommended in August (hybrid retrieval, threshold increase, LLM upgrade) were not contracted by Mercator. We should bring this up again at the Q4 review — not as an upsell, but as a genuine risk conversation. If the system keeps having quiet quality issues, the damage is to our reputation, not Mercator's.
