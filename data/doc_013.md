## Executive Summary

Iskratel is building internal AI capabilities across two teams: a network analytics team using LLMs for log parsing and anomaly detection, and a product team experimenting with LLM-assisted technical documentation generation. Both teams are currently running ad-hoc: models called directly via API, experiments tracked in spreadsheets, deployments done by hand, no shared infrastructure.

Kvant proposes building a lightweight MLOps platform tailored to Iskratel's scale — not a Kubernetes-and-everything enterprise setup, but a right-sized stack that gives both teams experiment tracking, model versioning, reproducible deployments, and shared access to a prompt/model registry. The goal is to stop reinventing infrastructure on every project and start building on a foundation.

**Proposed budget: €87,000 (phased across 3 phases)**
**Timeline: 20 weeks**
**Phase 1 only (if preferred): €32,000, 8 weeks**

## Problem Statement

Iskratel's AI teams are experiencing growing-pains infrastructure problems that are common at this stage:

- **No experiment tracking.** Results from different model configurations are compared informally. When a model regresses, there's no systematic way to identify what changed.
- **No shared model registry.** Each team maintains its own list of model versions and API keys. There is duplication and confusion about which model is deployed where.
- **Manual deployments.** Getting a new model version or prompt update into production requires manual steps that are error-prone and undocumented.
- **No evaluation framework.** The log parsing team evaluates model outputs informally; there is no standardized metric tracking or regression alerting.
- **No cost visibility.** API spend (primarily OpenAI, with some Anthropic) is billed to a single cost center with no breakdown by team or project.

These are not critical failures now. They become critical failures when the number of projects doubles, which is the trajectory Iskratel is on.

## Proposed Solution

A three-phase MLOps platform build, each phase delivering usable value independently.

### Phase 1: Experiment Tracking and Model Registry (Weeks 1–8)

**Experiment tracking:**
- MLflow deployment on Iskratel's existing GCP infrastructure (they have GCP credits and preference)
- Instrumentation support: Kvant helps both teams add MLflow tracking to their existing code
- Tracked: model name/version, prompt version, hyperparameters, evaluation metrics, cost per run

**Model and prompt registry:**
- Shared registry for model identifiers, API configurations, and prompt versions
- Version control for prompts (currently absent — prompts are in code with no versioning)
- Access control: team-level read/write, admin for registry management

**Cost tracking:**
- API spend attribution by team and project via LangSmith integration
- Monthly cost report (automated)

**Deliverable:** MLflow instance on GCP, instrumented for both teams, with registry and cost dashboard. Both teams onboarded.

**Phase 1 budget: €32,000**

---

### Phase 2: Deployment Pipeline and Evaluation Framework (Weeks 9–15)

**Deployment pipeline:**
- Docker-based deployment workflow with GitHub Actions CI/CD
- Staging and production environments for both teams' applications
- Automated smoke testing on deployment (configurable per application)
- Rollback capability (one-click via CLI or simple UI)

**Evaluation framework:**
- Standardized eval harness compatible with both teams' use cases
- For log parsing team: precision/recall on anomaly detection benchmark (to be built during Phase 2)
- For documentation team: LLM-as-judge evaluation (GPT-4o as judge, Phoenix for tracing)
- Regression alerting: Slack notification if eval metrics drop below threshold on deployment

**Deliverable:** CI/CD pipeline live, evaluation framework running on both teams' applications.

**Phase 2 budget: €31,000**

---

### Phase 3: Shared Infrastructure and Self-Service (Weeks 16–20)

**Shared model serving:**
- For open-weight models (Llama 3.1, Mistral) that Iskratel wants to run internally: vLLM deployment on GCP GPU instance (A100 or L4, depending on model size and budget)
- Cost comparison analysis: when does self-hosting beat API costs at Iskratel's projected volumes?
- Not recommending self-hosting by default — this phase scopes the option and implements it only if the economics make sense

**Self-service tooling:**
- Internal Streamlit dashboard for non-technical stakeholders: project status, cost by team, current model versions
- Runbook documentation for all components
- Handover training (full day, Iskratel team)

**Deliverable:** Optional self-hosted model serving, internal dashboard, full documentation and training.

**Phase 3 budget: €24,000**

## Assumptions

- Iskratel IT grants Kvant sufficient GCP access to provision compute resources and configure IAM roles; a dedicated GCP service account for Kvant will be required
- Both AI teams (network analytics and product) designate one technical contact who can spend approximately 4 hours/week on onboarding and instrumentation during Phase 1
- Existing applications are primarily Python; non-Python components (if any) may require additional instrumentation effort
- GitHub is Iskratel's version control system; if GitLab or another system is used, CI/CD configuration in Phase 2 will need adjustment (minor effort)
- Open-weight model self-hosting in Phase 3 is conditional on cost analysis results — we will not recommend it if API costs are more economical at Iskratel's scale

## Recommendation on Phasing

Given Tine's note about budget sensitivity: we recommend presenting Phase 1 as the primary offer with Phases 2 and 3 as optional extensions. €32,000 for experiment tracking and a model registry is a concrete, defensible value proposition. The full €87,000 requires Iskratel to believe in the long-term vision, which requires more trust than we have established with them yet.

We should be prepared for them to ask for a smaller Phase 1. We could scope a pilot at €15,000 covering MLflow deployment and one team's instrumentation — but at that point the scope is thin enough that a junior consultant could do it and the relationship risk is higher if something goes wrong. Our preference is to hold Phase 1 at €32,000 as the floor.
