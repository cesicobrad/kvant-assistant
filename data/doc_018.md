# Technical Report: Cost Comparison — OpenAI vs. Anthropic vs. Self-Hosted Llama 3.1
**Author:** Maša Vidmar
**Date:** 2024-09-23
**Audience:** Internal — informing pricing estimates for new proposals
**Status:** Current as of September 2024. Prices change. Check before using in a proposal.

---

## Context

Several recent client conversations (Iskratel, NLB Phase 2 scoping, Bisol) have included questions about self-hosted vs. API costs. This report gives our current working numbers based on actual client deployment costs and the Hetzner/GCP instance pricing we use.

This is a cost analysis, not a quality analysis. Quality differences between models are real and significant; this document focuses only on cost per token at realistic deployment scales.

---

## Assumptions

- "Small deployment": 500 queries/day, avg. 1,500 tokens input + 600 tokens output per query
- "Medium deployment": 2,500 queries/day, avg. 2,000 input + 800 output
- "Large deployment": 10,000 queries/day, avg. 1,800 input + 700 output
- All API prices as of September 2024
- Self-hosted on Hetzner GX2-120 (2× A100 80GB, €4.89/hour, or €3,532/month)
- Self-hosted model: Llama 3.1 70B (requires 2×A100 for comfortable serving with batching)

## Self-Hosted Break-Even Analysis

Self-hosted Llama 3.1 70B on Hetzner GX2-120 costs ~€3,532/month in compute (plus ~€50/month storage and ops overhead = ~€3,580/month).

| Comparison | Break-even query volume |
|------------|------------------------|
| vs. GPT-4o | ~7,800 queries/day |
| vs. GPT-4o-mini | ~132,000 queries/day |
| vs. Claude Sonnet 4.5 | ~5,300 queries/day |
| vs. Claude Haiku | ~67,000 queries/day |

Break-even is at approximately 7,800 queries/day vs. GPT-4o. None of our current clients are near this volume. Self-hosting is not cost-effective for any existing Kvant client at current scales.

However, these numbers do not include:
- Engineer time for model management, updates, and incident response (~0.5 FTE ongoing)
- Quality difference: Llama 3.1 70B is meaningfully worse than GPT-4o on complex reasoning and Slovenian-language tasks in our testing
- Latency: self-hosted throughput depends on batch size and request patterns; not directly comparable to API latency

## Quality vs. Cost Trade-Offs (Practical Experience)

From our deployments:

**GPT-4o-mini** is adequate for simple retrieval and classification tasks. We used it on Mercator Polica under client budget pressure and the quality trade-off was noticeable on complex queries. Do not recommend for primary generation on multi-hop or analytical questions.

**Claude Haiku** is our preferred low-cost option for customer-facing applications (Mercator chatbot scoping). Latency is excellent, Slovenian handling is better than GPT-4o-mini in our informal tests. Price-to-quality is competitive.

**GPT-4o** is the default for complex generation tasks. For regulatory or technical domains where hallucination risk is highest, the quality difference vs. mini/Haiku justifies the cost at small and medium deployment scales.

**Claude Sonnet 4.5** is competitive with GPT-4o on quality but more expensive at current pricing. We have not yet had a client deployment that defaulted to Sonnet 4.5, but the output quality on structured tasks is strong and it is worth evaluating for document-heavy workflows where output quality matters more than cost.

## Recommendation for Proposals

Use these monthly cost estimates when scoping:

| Use case | Recommended model | Estimated monthly API cost |
|----------|-------------------|---------------------------|
| Internal knowledge assistant (small team) | GPT-4o | €50–150 |
| Customer-facing chatbot (medium volume) | Claude Haiku | €80–200 |
| Document extraction pipeline | GPT-4o-mini | €30–90 |
| Regulatory / high-stakes generation | GPT-4o | €150–500 |
| Fine-tuning evaluation (one-time) | GPT-4o | €20–80 |

Self-hosting: only worth discussing with clients above 5,000 queries/day, and only if data residency or privacy requirements make API usage problematic. At that scale, bring in Maša before making any commitments.
