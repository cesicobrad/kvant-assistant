## Context

Bisol has been using a GPT-3.5-turbo-based chatbot (built by a third party in 2022) to handle customer queries about solar panel products, installation requirements, and financing options. The bot performs adequately on simple product questions but struggles with technical queries (inverter compatibility, grid connection requirements by municipality, warranty claim procedures) and frequently gives generic answers that frustrate technically literate customers.

Bisol asked Kvant in October to evaluate whether fine-tuning would improve performance over their current prompt-engineering-only approach. This proposal scopes that evaluation and, if fine-tuning is recommended, the fine-tuning implementation.

---

## What We're Proposing

A two-stage engagement:

**Stage 1 — Evaluation (4 weeks, €6,500):** Establish a baseline on the current system, determine whether fine-tuning or RAG (or both) is the right intervention, and deliver a written recommendation. This stage stands alone — Bisol can stop here.

**Stage 2 — Implementation (8 weeks, €19,000):** Implement the recommended solution based on Stage 1 findings. This is only contracted if Stage 1 recommends proceeding and Bisol approves.

Total if both stages proceed: **€25,500**

---

## Stage 1: Evaluation Methodology

We will construct a 60-question evaluation set covering:
- Simple product lookup (expected: current system handles well)
- Technical compatibility queries (expected: current system struggles)
- Municipality-specific regulatory questions (expected: current system fails — this is out-of-training-data territory)
- Warranty and claims process queries (expected: inconsistent)

We will test the current GPT-3.5-turbo system, a GPT-4o-mini RAG system grounded on Bisol's product documentation and installer guides (~150 documents), and a fine-tuned GPT-4o-mini on a held-out set from Bisol's historical query/response logs (if logs are available and of sufficient quality).

Our hypothesis is that RAG will outperform fine-tuning for the municipality-specific and regulatory queries (knowledge grounding problem, not behavior problem), while fine-tuning may help on response tone and technical precision. The evaluation will confirm or refute this.

Deliverable: written evaluation report with benchmark scores, architectural recommendation, and go/no-go recommendation for Stage 2.

---

## Stage 2: Implementation (if recommended)

Most likely recommendation based on our prior assessment: a hybrid approach — RAG over product/regulatory docs, with fine-tuning on Bisol's historical query logs to align response style and technical vocabulary. If Bisol's query logs are insufficient for fine-tuning (minimum ~500 high-quality examples needed), we will recommend RAG only.

Implementation would target deployment on the existing chat widget Bisol uses (vendor TBD — they mentioned Intercom; we need to confirm API access).

---

## Assumptions

- Bisol can provide historical query/response logs (export from existing chatbot or customer support CRM) for fine-tuning evaluation. If not available, Stage 2 will be RAG-only and cost may be revised down.
- Product documentation (~150 documents) is available in machine-readable format.
- Fine-tuning will use OpenAI's fine-tuning API (GPT-4o-mini); alternative open-weight approaches (Mistral, Llama 3.1) are possible but would require additional infrastructure and are outside this scope.

The Stage 1 evaluation is the honest stage — we will tell Bisol if fine-tuning is not worth the investment. We have done this before and lost the Stage 2 work. We would rather do that than oversell.
